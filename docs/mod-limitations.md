# 当前测试版限制与存读档建议

更新：2026-11-15。此说明针对当前 T60 动力装甲控制器，不代表公开稳定版已验收。

## 外观分配额度

- 每个游戏进程中的当前控制器最多累计创建 **16 个动力甲外观数据对象**。这不是“只能穿脱16次”，也不是允许同时穿甲的人数承诺。
- 同一角色、同一外观实例和同一原始外观数据保持不变时，普通穿脱会复用已有对象，通常不增加额度。
- 读档、世界重置、角色外观实例重建，或角色加载通知导致缓存失效后，再次穿甲可能创建新对象并消耗额度。一次读档可能影响多位穿戴者，不能换算成固定可读档次数。
- 达到16个后，控制器拒绝创建第17个对象，受影响角色可能无法显示动力甲，并尝试恢复普通外观。实际防护与装备数据不因此等同于消失；本轮未对玩家现场验证该状态。
- 脱甲、F11恢复、返回主菜单或同一进程重新读档都不保证回收额度；F11只恢复控制器开关/解除角色阻塞，不清零累计分配。

### 遇到不显示时

先备份并正常保存，**完整退出 Kenshi，再正常启动并读档**。这是开启新进程的临时办法，不是资源回收已修复。游戏中反复穿脱或按F11不能解决已耗尽的分配额度。

个别附件加载超时也会导致普通身体正常而动力甲不显示。若仍有分配余量，一次F11曾在玩家现场恢复；此问题的具体等待原因尚未根治。若日志是启动门禁错误（例如 cache bootstrap -31/-30），需使用配套骨架和插件，F11同样不能修复。

## 存读档与稳定性

当前已在独立单人档验证一次保存、三次读回，人物字段与原始外观保存字段一致；这不覆盖完整递归库存、多人连续读档、长期稳定性或全部引擎容器。

历史二次读档曾发生原生崩溃。已有有限保护，但原失败分支尚未在修复后的实机中命中，**不能承诺已根治**。建议保留多个独立存档槽；若连续读档后出现异常，停止该轮操作，保留日志，正常退出后再继续。不要在缺失模组依赖时加载原世界。

## 为什么暂时保留上限

保存读者计数归零、Lua缓存清空、模型消失都不能证明引擎和渲染任务不再引用旧外观。当前没有经过验证的生产对象安全释放协议，因此暂不清零、扩大上限或跨读档复用旧指针，以免把显示限制变成崩溃或存档风险。

这属于测试版已知限制，后续继续修复。若无法接受频繁重启或潜在存读档异常，请等待后续稳定版。

开发证据与未验证边界见 [本轮调查](handoffs/save-load-limits-20261115.md) 和 [保存生命周期记录](handoffs/save-lifecycle-20261105.md)。
